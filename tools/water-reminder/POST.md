## 主版本（约 600 字，头条 / 公众号通用）

**标题：上班老忘喝水？我写了个 8 MB 的小工具，只在工作时间烦你**

久坐一天，下班才发现水杯还是满的。

网上喝水提醒的 App 不少，我都不太想装：要么得先装个 Python，要么下个 40 MB 的 exe 被杀软拦一道，要么一直挂在后台吃掉几十兆内存。

后来自己写了一个，顺便把几个我觉得别扭的地方都改掉了。

**它长这样**

到点了右下角弹一张毛玻璃卡片，进度直接写在上面：

> **接杯水，顺便看看窗外**
> 今日 1250 / 2000 ml，还差 750 ml
> 　[ 喝了 250 ml ]　[ 15 分钟后 ]　[ 今天不提醒 ]

点一下「喝了 250 ml」就记一笔，不用打开任何窗口。不理它 30 秒自己收起，
并且当成"你没看见"——15 分钟后再追一次，连追两次还没理就回归正常间隔，不跟着吵。

**几个我特意做的细节**

- **只在工作时段提醒**（默认 9:00–18:00），下班不烦你；填成 22:00–06:00 上夜班也认
- **一进工作时段先提醒一次**：早上打卡、午休结束、暂停到点，都不用等满一个钟头
  （这条是被我自己吐槽出来的——以前 8:30 坐到工位上，它要干等到 9:30 才响）
- **午休自动跳过**（12:00–13:00），这个几乎所有同类工具都没做
- 鼠标停在托盘图标上就知道"现在为什么不弹"：暂停中 / 今天已静音 / 不在时段 / 下一杯几点
- 达成 2000 ml 弹一次庆祝，当天就不再打扰
- 缩在托盘里，不占任务栏；右键能「记一杯」「撤销上一次记录」「暂停 1 小时」「开机自启」
- 弹提醒时有一声轻提示音，怕吵可以在设置里关掉
- 深色 / 浅色 / 跟随系统，ml / oz 单位可切换
- 提醒文案随便改，默认那 12 条是打工人梗
- 数字填歪了不会崩，会被收进合理范围，界面上写明"提醒间隔 9999→480"
- 每一次弹与不弹都写在 exe 同目录的 `run.log` 里，"到底有没有提醒"翻日志就知道
- 手滑点了「退出」不算退，8 秒内点第二次才真退；双击第二个 exe 会把正在跑的那个唤到前台

**它有多轻**

- 单文件 exe **8 MB**，双击就跑，不用装任何运行库
- 常驻内存 **20 MB** 上下，空闲时 CPU 实测 0%
- **零第三方依赖**，只用 Python 标准库和系统自带能力
  （所以没有"又要装 xxx"这一步，杀软也没什么可报的）

**代码是开源的**

界面是 Tk 的 Canvas 自绘的，托盘是手写的 `Shell_NotifyIcon` 加一个独立消息线程，连图标都是标准库自己抠底、缩放、拼成多尺寸 ICO 的——不需要 Pillow。

五个文件，将近四千行：

- `core.py` 配置与存储
- `main.py` 调度与托盘交互
- `win32ext.py` 窗口 / 托盘 / 自启动（纯 ctypes）
- `ui.py` 自绘控件
- `icon.py` 图标兜底生成

另外配了 130 多项测试：67 条 `unittest` 用假时钟走完整调度（不建窗口、不碰注册表），
22 项界面真渲染自检（用临时目录，不会动你自己的配置），48 项 Win32 接口自检。"到点到底弹没弹"这种只能盯着屏幕验证的事，现在写成断言了。

想抄哪段随便拿，MIT。

**源码 / 下载**：[GitHub 链接]

数据全在本机 `data` 文件夹里，不联网、不上传。

## 掘金版可以多加的技术段落（挑 2-3 个写，别全放）

这几条都是真踩出来的，同行爱看，也最容易被评论区挑错——写对了能攒信用：

- **无边框窗口一按就闪退**：网上教程最多的拖动写法
  `ReleaseCapture() + SendMessageW(hwnd, WM_NCLBUTTONDOWN, HTCAPTION, 0)`
  在 Tk 事件回调里会进入 Windows 的模态移动循环 → Tcl 解释器被重入 →
  `Fatal Python error: PyEval_RestoreThread: NULL tstate`，退出码 `0xC0000409`。
  改成纯 Tk 事件（`<ButtonPress-1>` 记偏移、`<B1-Motion>` 里 `geometry("+x+y")`）之后不复现。
  60 行最小复现程序分别验证了 `ncm` 必崩、`tk` 正常
- **ctypes 的两个签名坑**：回调不声明 `argtypes`，64 位 `lparam` 会被当 C int 截断；
  **返回值**不声明 `restype`，`GetModuleHandleW` 拿到的 `0x7FF6xxxxxxxx` 被截成垃圾值再当
  `hInstance` 传给 `CreateWindowExW`，托盘线程反复 access violation
- **高分屏**：必须在建任何窗口之前 `enable_dpi_awareness()`，否则整个界面被系统位图拉伸、文字发糊；
  之后所有布局坐标乘缩放因子、字体用负数字号，**且只能缩放一次**
- **玻璃质感的取舍**：`-transparentcolor` + `SetWindowCompositionAttribute`（亚克力）
  这套在部分机器上拖动就崩，而且透明像素会点击穿透。最后改成实色玻璃拟态
  （实底窗色 + 等效混色卡片 + 1px 亮边 + 顶部高光带 + DWM 圆角 + CS_DROPSHADOW），观感接近但稳定
- **图标全程不用 Pillow**：手写 PNG 解码 → 抠品红底 → 裁切补方 → alpha 加权盒式缩放 → 拼多尺寸 ICO。
  AI 出的"纯色底"其实是带 JPEG 噪点的 (244,9,233)，按理论值 #FF00FF 归一化会给整张背景留一层
  alpha≈65 的灰雾；要从边框实测背景色、按不透明量定外接框。16/24 这两帧还得按轮廓重画，
  不然 1024 的高光缩到 16px 直接糊成一团
- **"到点不提醒"的排查**：不是 bug 是设计——进时段排的是 `now + interval`，
  8:30 打卡要干等到 9:30；弹窗 30 秒自收且不留痕迹。现在写进 `run.log` 并用假时钟断言钉住
- **windowed 打包后崩了看不到栈**：有效手段只有三个——跑源码 + `PYTHONFAULTHANDLER=1`；
  数 `%LOCALAPPDATA%\CrashDumps\*.dmp` 的新增；事件日志 ID 1000/1001 取异常码和出错模块
