## v0.9.0 — 2026-10-09

这一版是做了一次从头到尾的专业审阅（架构 / 功能 / 体验 / 界面）之后，
把审出来的 26 条全部落地，再用两套测试把改动的地方钉住。

### 提醒逻辑（改动最大）

- **一进工作时段立刻先提醒一杯**，不用等满一个间隔。早上打卡、午休结束、
  暂停到期三种情况都算"刚进时段"。以前 8:30 坐到工位要干等到 9:30 才响第一杯
- 同一时段内改设置**不会**立刻弹窗（改个数字就被糊脸很烦），只重排计时
- 弹窗 30 秒没人点自动收起后，**按"没看见"处理**：自动顺延 `snoozeMinutes`
  （默认 15 分钟）再追一次；连续两次没人理就回归正常间隔，不跟着吵
- 达成目标的庆祝窗不追提醒（`missable=False`）
- 弹窗倒计时写清楚"几秒后收起、没人点会怎样"，不再出现"双击托盘可以再打开"
  这种其实不存在的指引
- 弹提醒时带一声系统轻提示音（`sound`，可关），不用第三方库
- 托盘提示（悬停 tooltip）直接写"现在为什么不弹"：暂停中 / 今天已静音 /
  不在时段 / 下一杯几点

### 界面

- 深色 / 浅色 / 跟随系统三档（`theme`）。两套配色是分别调的两张配方表，不是反色
- 显示单位可选 ml / oz（`unit`）。存储与填写永远是毫升，只影响界面怎么写
- 提醒弹窗按文案行数自适应高度，长文案不再被裁掉
- 进度条改成渐变 + 端点圆帽；7 天柱状图区分达标 / 未达标 / 无数据三色，
  加今天标记和目标虚线
- 设置窗：`—` 收起、`×` 销毁，Ctrl+S 保存，输入框回车即保存，数字加千分位
- 未开自启时，设置里显示一行琥珀色提醒；点 `—` 收起时托盘上方弹一次短提示，
  避免"程序还在跑吗"这种猜
- 时段填成 22:00–06:00 这种跨夜夜班正常支持，界面标"（跨夜）"

### 入口与交互

- 双击第二个实例不再只是弹提示框走人，而是**把已经运行的那个界面唤到前台**
- 托盘菜单补齐：打开设置 / 立刻提醒一次 / 记一杯（带上具体毫升数）/ **撤销上一次记录** /
  暂停 1 小时（暂停中这条变成「取消暂停」并带打勾）/ 今天不再提醒（已静音时变成「恢复今天的提醒」）/
  开机自启（带打勾）/ 退出
- 设置窗底部有「打开数据目录」，直接跳到 `config.json` 和 `data\` 实际所在的那个位置
  （便携和 APPDATA 两种情况路径不一样，翻日志不如点这一下）
- 手滑点「退出」不会立刻退：8 秒内点第二次才算确认
- 开机自启以注册表实际状态为准，写不进去（组策略 / 安全软件）时开关自己弹回去并在日志说明

### 内核与健壮性

- Tk 回调、主线程、托盘线程的未捕获异常全部进 `run.log`。
  windowed 打包后没有控制台，不接住的话表现就是"程序看着还在，到点不提醒"
- 用户填的数字统一夹进合法区间（间隔 5–480 分钟、单次 50–2000 ml、目标 200–10000 ml、
  顺延 5–120 分钟），并在界面上写明"哪一项从多少改成了多少"，输入框直接显示生效值
- 时间字段（`"9:5"`、`"25:00"`、空串）有单独校验和回落规则，坏值不炸
- `config.json` 写坏时原件另存 `config.json.bad-时间戳`，这次先用默认值，界面告知备份位置
- 配置和数据改成原子写（tmp + fsync + `os.replace`），写到一半断电不会留下半截文件
- 记录一天一个 JSON，超过 400 天自动挪进 `data\archive\`（只挪不删）
- `run.log` 超 512 KB 自动轮转
- 主循环从"15 秒轮询"改成**单条 `after(500ms)` 心跳 + 墙钟唤醒**：
  到点立刻醒，空闲时不读盘不判断，实测空闲 CPU 0%
- 数据目录：优先 exe 同目录（便携）；不可写时自动改用 `%APPDATA%\WaterReminder\` 并在日志说明
- 托盘 HICON 缓存 + 退出时 `DestroyIcon`（以前每次刷新漏一个图标句柄）
- 窗口位置：按光标所在显示器取工作区（`SPI_GETWORKAREA` 只有主屏，双屏会算错）；
  拖动后钳制在可见范围内

### 图标

- 不再运行时自算。开发期用 `make_icon.py`（纯标准库：手写 PNG 解码 → 抠品红底 →
  裁切补方 → alpha 加权盒式缩放 → 拼多尺寸 ICO）从母图生成 `assets/app.ico`
  （16/24/32/48/64/128/256）随 exe 打包
- **16/24 这两帧按母图轮廓重画**：1024 的高光缩到 16px 会糊成一团，看不出是水滴。
  重画保留外形 alpha，边缘用阈值收硬、重新铺纵向渐变和高光，小尺寸再套一遍收紧半透明边
- 托盘按 `SM_CXSMICON` 取对应那一帧，不让系统二次缩放
- `src/icon.py` 降级成"资源缺失时现画一个兜底"，启动日志写明用的是随包还是自算

### 打包

- exe 有了真的文件元数据：文件说明 / 公司 / 版权 / FileVersion / ProductVersion
  都来自 `core.VERSION`，`build.py` 生成 `--version-file` 传给 PyInstaller
- 输出目录统一在 `build/`，`dist/WaterReminder.exe` 8.0 MB，仍然 `--onefile --windowed --noupx`
  （开 UPX 会明显提高杀软误报率，宁可大两兆）

### 测试（这轮新加的，两套）

- `tests/test_core.py`（40 项）：配置纠正与旧键名兼容、坏配置备份、原子写、
  时段与跨夜判断、存储增删计数与撤销、连续天数、归档、单位换算、日志轮转
- `tests/test_schedule.py`（27 项）：假时钟走完整调度（进时段先弹 / 同时段重排不许立刻弹 /
  没人点顺延 / 到上限回归 / 响应归零 / 午休 / 周末 / 暂停 / 今天不提醒），
  以及托盘菜单构造、撤销、二次确认退出。**全程不建真实窗口、不写注册表**
- `tests/ui_check.py`（22 项）：真机渲染检查，用临时目录，不碰真实数据与自启注册表。
  覆盖双主题重建、单位显示、长文案自适应高度、倒计时不换行、提示条自收、
  屏幕外窗口找回、文字与柱状图不相交、退出收口
- `tests/smoke.py`（48 项）：Win32 边界计算、图标、单实例、显示器工作区、自启命令行

三项合计 137 项，跑法见 README 的「跑测试」。

### 顺手修掉的五个缺陷（都是实测/截图才看见的）

- 选「浅色」不换配色：主题变更判断读的是 `collect` 之前的旧值
- 单位非毫升时设置窗顶部提示**一直**显示：比较用了中文标签，而 `unit_label()` 返回 `ml`/`oz`
- 从托盘重新唤起时窗口大半还在屏幕外：`keep_in_view` 走了拖动那套"至少露 40 像素"的
  底线，那是给拖动用的；改成按窗口中心所在显示器整扇拉回
- **「连续达标 N 天」被柱状图压住**：那行字右对齐在 `(W-20, 210)`，而 7 天图的绘制区
  正好从 `x=132` 铺到 `x=W-20`、纵向 188–222 —— 最右边那根柱子直接盖在字上。
  挪到卡片右上角、和「今日进度」同一基线（`y=92`）。
  界面自检里补了一条几何相交检查（`ui_check.py` 第 22 项），并验证过它**确实会红**：
  把坐标改回旧值，那条就 FAIL
- 设置里「午休免打扰」（时间段的标题）和右边开关的「午休不打扰」挨在一起，
  读起来像同一项写了两遍 → 左边改成「午休时段」
