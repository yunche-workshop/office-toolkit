# 仓库规划与发布流程

> 这个仓库是「工具免费送，靠文章赚广告钱」的引流终点。
> 所以它要满足两件事：**让人一眼看懂能下什么**，**别把账号搞风控**。

---

## 一、仓库定位

**一个仓库装所有工具（monorepo）**，不一个工具一个仓库。

理由：

- 引流终点只有一个，文章里挂的链接不会变
- star / fork 集中在一个仓库，比分散在 10 个仓库好看
- 清单体文章（"5 个免费办公小工具"）天然对应一个仓库
- 新建仓库本身有频率限制，还容易触发风控

代价：单个工具不能单独打 tag。可接受——工具之间本来就互相引流。

---

## 二、目录规范

```
tools/<工具名-英文短横线>/
├─ README.md      必填：截图 + 能干什么 + 怎么用 + 技术实现
├─ src/           源码
├─ tests/         自检脚本（可选）
├─ assets/        图标等静态资源
└─ build.py       打包脚本
```

新增工具时的硬性要求：

1. **零第三方依赖**（只用 Python 标准库 + 系统自带能力）——这是所有工具的统一卖点，破了就没差异化了
2. 单文件 exe，**体积控制在 15 MB 以内**
3. 数据写本地，不联网
4. README 里必须写清楚「和别的方案有什么不一样」

---

## 三、发布流程（手动，一步步来）

```
1. 本地开发 → python tests/smoke.py       逻辑自检
2. 本地打包 → python build.py             出 dist/*.exe
3. 真机验证 → 双击 exe，跑一遍主流程      这步不过不许推
4. 提交代码 → git add / commit（一次一件事）
5. 打 tag   → git tag v1.0.0
6. 推代码   → git push（确认后再推）
7. 发 Release → 网页手动上传 exe 附件
```

**exe 只通过 Release 附件分发，不进 git。** 仓库里不放二进制。

## 四、账号风控红线（重点）

之前账号被限制过一次，原因大概率是**用 GitHub Actions 频繁编译**。以下都是硬红线：

### 绝对不做

- ❌ **不用 GitHub Actions 编译任何东西**（不建 `.github/workflows/`）
  → 打包全部在本地完成，只 push 源码
- ❌ 不用 GitHub Actions 做定时/循环任务
- ❌ 不写自动 push 的脚本、不搞 commit 机器人、不伪造提交频率
- ❌ 一个仓库里塞大文件（单个文件 > 50 MB 会被警告，> 100 MB 直接拒）
- ❌ 不把 exe / 打包产物 / data 目录提交进仓库

### 注意节制

- ⚠️ **push 频率**：一天几次正常，几分钟一次连续几十次不正常
- ⚠️ **Release 频率**：一个版本一次，不要拆成十几个
- ⚠️ **仓库数量**：短期不要批量新建几十个仓库
- ⚠️ 附件总体积：Release 附件控制在 20 MB 以内（我们现在 7.6 MB，很安全）
- ⚠️ 不用代理/VPN 频繁切换 IP 登录

### 出事怎么办

被限制了就走官方申诉（help.github.com 的账号恢复流程），别换号绕——换号属于规避封禁，会加重。

## 五、版本节奏

| 阶段 | 目标 |
|---|---|
| 第 1-2 个工具 | 验证「写完能发」的闭环，不追求量 |
| 攒够 5-6 个 | 发一期清单体合集文章（这类最容易起量） |
| 之后 | 每新增一个工具：单工具短推一次，攒够再合集 |
